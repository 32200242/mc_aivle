# 지역·센터·상담인력 연결 데이터 설계

## 구현 결과

관리자 대시보드는 `지역 → 센터 → 상담인력 → 내담자군 → 일별 운영지표`를 키로 연결합니다. 전국 화면에서 17개 시·도 타일을 누르면 해당 지역 집계와 센터 목록으로, 센터를 누르면 그 센터의 상담인력·내담자 문제영역·대기·이용률·만족도·일별 추이로 범위가 바뀝니다. 예측 화면도 동일한 API를 사용합니다.

화면에는 실제 운영 화면처럼 지표만 표시합니다. 다만 현재 파일은 개인정보가 없는 시연용 생성 데이터이므로, `backend/data/dashboard_demo/metadata.json`과 이 문서에는 그 사실과 한계를 명확히 기록합니다. 실서비스에서 실제 실적으로 교체하기 전에는 의사결정 근거로 사용하면 안 됩니다.

## 데이터 관계

```text
regions.id
  └─ centers.region_id
       ├─ counselors.center_id
       │    └─ client_cohorts.counselor_id
       └─ daily_center_metrics.center_id + date
```

| 파일 | 기본키/단위 | 용도 |
|---|---|---|
| `regions.csv` | 지역 17행 | 인구·가구·기관 수·2022년 전체 서비스 이용자 앵커 |
| `centers.csv` | 센터 244행 | 지역·기관유형·수요가중치·인력 정원 |
| `counselors.csv` | 상담인력 1,724행 | 상근/위촉·경력·역량·상담 수용률·현재 담당 규모 |
| `client_cohorts.csv` | 상담사×주요 문제영역 | 개인식별정보 없이 현재 담당 내담자를 집계군으로 연결 |
| `daily_center_metrics.csv.gz` | 센터×일자 185,440행 | 760일 상담·신규·종결·대기·만족도·슈퍼비전·AI 기록시간 |
| `model_leaderboard.csv` | 후보모델·앙상블 5행 | rolling-origin 검증 MAE/MAPE와 앙상블 결과 |

## 근거와 보정 규칙

- 기관망 총계는 한국건강가정진흥원의 현재 평가대상 244개소(가족센터 223, 건강가정지원센터 9, 다문화가족지원센터 12)를 사용합니다.
- 17개 시·도별 기준 배치는 2024년 성과관리 연구의 통합 가족센터 212개 분포를 사용하고, 이후 기관망 총계 차이는 인구·가구·기존 분포를 해치지 않는 범위에서 기관 유형별로 보정했습니다. 따라서 개별 기관의 실제 명칭·설치 현황을 재현한 목록은 아닙니다.
- 상담인력은 2024년 212개 센터 1,497명이라는 조사값과 센터당 상근 1.65명, 위촉 6.09명이라는 조사값을 함께 사용해 현재 244개소 규모에 맞춰 1,724명으로 배분했습니다. 상근은 센터당 최소 1명, 위촉은 최소 2명이 되도록 한 뒤 수요 가중치로 나머지를 배분했습니다.
- 전국 연간 누적 상담 참여인원 기준은 2024년 307,035명이며, 부부 34.37%, 부모-자녀 26.25%, 기타 가족관계 32.30%를 핵심 문제영역 비중에 반영했습니다.
- 지역 수요 가중치는 2023 인구·가구와 2022 가족센터 전체 프로그램 이용자 수를 45:55로 혼합했습니다. 전체 프로그램 이용자 수는 상담만의 실적이 아니므로 지역 상대수요를 보정하는 보조변수로만 씁니다.
- 만족도 중심값은 가족상담 프로그램 조사 평균 3.92/5를 사용했습니다. 실제 센터별 만족도를 의미하지 않습니다.
- 가족위기 점수의 임계값은 개인 예측에 쓰지 않습니다. `일반/모니터링/집중검토` 인원은 운영상 사례검토량을 표현하는 집계 밴드이며 임상판정이 아닙니다.

## 일별 생성과 재현

프로젝트 루트에서 다음 명령을 실행하면 기준일을 포함한 과거 760일 데이터를 다시 만듭니다.

```powershell
& ".\.venv\Scripts\python.exe" ".\backend\scripts\export_dashboard_dataset.py" --as-of 2026-08-03
```

기준일과 `SEED=20260803`이 같으면 동일한 결과가 나옵니다. API는 저장된 CSV/GZIP과 전국 스냅샷을 기준 데이터로 사용하고, 요청 기준일과 저장 기준일의 차이만큼 날짜만 이동합니다. 따라서 서버 요청마다 18만여 개의 시연 행을 다시 생성하지 않으며, 읽은 데이터와 범위별 예측 결과는 메모리에 캐시합니다.

## 생성 규칙 상세

모든 난수는 Python `random.Random(20260803)` 한 스트림에서 순서대로 생성합니다. 따라서 같은 코드·기준일·시드에서는 지역, 센터, 상담사, 집계군, 일별지표가 전부 동일하게 재생성됩니다. 생성 데이터는 실제 기관이나 사람의 행을 복제하지 않고 공식 총계·분포를 만족하도록 만든 운영 시뮬레이션 자료입니다.

|---|---|---|
| 지역·기관 | 17개 시·도, 전체 244개소를 기관유형별 총계에 맞춤 | 2025 고도화 연구의 조사 모집단 244개소와 2024 성과관리 연구의 지역 분포를 결합 |
| 센터 수요가중치 | `(지역 인구비중÷기관수)×0.45 + (2022 전체서비스 이용자비중÷기관수)×0.55`, 센터별 log-normal 변이 `σ=0.18` | 인구·가구만 쓰면 서비스 접근성이 빠지고, 전체 이용자만 쓰면 상담 외 사업이 섞이므로 보조변수로 혼합 |
| 상담인력 | 총 1,724명 중 상근 403명, 위촉 1,321명. 센터당 상근 최소 1명·위촉 최소 2명 후 수요가중치로 잔여 배분 | 212개소 1,497명과 설문 평균 상근 1.65명·위촉 6.09명을 현재 기관망 규모에 보정 |

요일계수는 월~일 순서로 `1.24, 1.25, 1.20, 1.18, 1.05, 0.75, 0.33`이고 월계수는 1~12월 순서로 `0.88, 0.92, 1.08, 1.05, 1.02, 1.01, 0.94, 0.84, 1.09, 1.08, 1.06, 0.93`입니다. 이 계수는 공식 통계가 아니라 주중 운영·방학·연말 변동을 표현하기 위한 시연 가정입니다. 실데이터 연결 후에는 센터 휴관일·공휴일·예약정책·캠페인 변수를 사용해 재추정해야 합니다.

## 예측 모델과 대기 운영계획

수요예측과 대기계산을 한 모델로 섞지 않고 두 단계로 분리합니다.

### 기관 목표 참고선

- 2026년 가족상담 서비스 이용자 목표: 304,699명
- 2026년 가족상담 서비스 이용자 만족도 목표: 93.0점
- 출처: 한국건강가정진흥원 「2025~2029년 중장기경영목표」
- 전국 그래프는 연간 이용자 목표를 12개월로 나눈 월평균을 표시합니다.
- 지역·센터 그래프는 최근 누적 상담 참여인원 비중으로 전국 월평균 목표를 배분합니다. 이는 운영상 비교선이며 센터별 성과 할당량이나 평가 기준이 아닙니다.
- 예측 엔진은 요일·시차 정보를 보존하기 위해 일별 자료로 학습하지만, 화면에서는 일별 변동을 줄이도록 완료 월 합계와 향후 28일 합계를 표시합니다.

### 1단계: 상담 수요 앙상블

1. 최근 84일을 28일짜리 3개 rolling-origin 검증창으로 구성합니다. 각 창에서는 그 이전 데이터만 학습하고 다음 28일을 재귀 예측하므로 미래 시차값 누출을 막습니다.
2. 후보는 요일 계절 나이브, 최근 4주 동일요일 평균, Ridge, Boost 네 종류입니다.
3. Ridge와 Boost의 입력은 선형 추세, 요일·연간 sin/cos, 1·7·14·28일 시차, 최근 7·28일 평균입니다.
4. Boost는 기본 설치에서는 40개 회귀 stump를 순차 적합하는 내장 Gradient Boosting을 사용합니다. `requirements-forecast.txt`를 설치하면 깊이 3, 학습률 0.04, 180개 트리의 XGBoost `hist` 엔진으로 자동 교체됩니다.
5. 네 후보의 검증 예측을 5% 단위 비음수 가중치, 가중치 합 100% 조건에서 탐색하여 MAE가 가장 작은 조합을 선택합니다. 단일모델 가중치 100%도 후보에 포함되므로 앙상블이 검증 최우수 단일모델보다 구조적으로 나빠지지 않게 합니다.
6. 예측구간은 세 검증창의 절대오차 90백분위를 다음 28일 전망에 가감합니다. 정규성 가정을 강제한 신뢰구간이 아니라 최근 오차 기반 운영 범위입니다.

XGBoost는 비선형 임계효과를 보완하지만 추세 외삽에는 약할 수 있어 단독 고정하지 않습니다. Ridge의 안정적 추세, 계절 기준선, Boost의 비선형성을 검증가중 앙상블로 결합합니다. 대상은 개인 상담성과나 위기 가능성이 아니라 전국·지역·센터의 일별 상담 참여인원입니다.

### 2단계: Erlang-C 예약 대기압력

앙상블의 일평균 전망을 도착률 `λ`, 상담사별 일일 슬롯을 처리율 `μ`, 상담인력 수를 서버 수 `c`로 두고 M/M/c(Erlang-C) 근사를 계산합니다. 화면에는 예상 상담 수용률, 대기압력, 85% 목표 상담 수용률을 맞추기 위한 추가 일일 슬롯 수만 표시합니다.

- 가정: 포아송 도착, 독립·동일한 지수 처리시간, 무한 대기공간, 대기 중 이탈 없음.
- 한계: 가족상담은 예약제이고 상담사 전문영역·회기 길이·취소·재예약이 달라 Erlang-C 가정을 정확히 만족하지 않습니다.
- 사용범위: 인력·예약 운영 시나리오의 참고값. 현재 대기자 명단, 개인 위험도, 임상판정에 사용하지 않습니다.

## 실제 백엔드 교체 지점

- API 계약: `GET /api/v1/admin/dashboard?region_id=SEO&center_id=CTR-SEO-001&days=90`
- 현재 저장소: `backend/app/services/operational_data.py`
- 프론트 타입: `frontend/lib/types.ts`의 `DashboardSummary`
- 전국/지역/센터 화면: `frontend/app/admin/dashboard/page.tsx`
- 예측 화면: `frontend/app/admin/analytics/page.tsx`

실서비스 전환 시에는 API 응답 계약을 유지하고 `get_operational_dataset()`만 DB/데이터마트 조회 구현으로 바꾸면 됩니다. 권장 원천 테이블은 `organization`, `staff_assignment`, `case_enrollment`, `session_fact`, `assessment_fact`, `satisfaction_fact`, `supervision_fact`입니다. 사람 식별자는 대시보드 API에 보내지 말고 센터·일자·문제영역별 최소 집계만 전달합니다.
